# 0001. 使用架构决策记录保存设计依据

- 状态：已接受
- 日期：2026-11-14

## 背景

项目长期演进时，最难追溯的是各项决策背后的原因。设计依据如果分散在合并请求、聊天记录和 Wiki 中，就会逐渐失效，甚至彼此矛盾。

## 决策

使用轻量级的架构决策记录文件保存重要的架构决策。文件统一放在 `docs/decisions/`，命名为 `NNNN-title.md`，按顺序编号，编号不得复用。

当某项决策被后续决策取代时，在原文件中标记 `superseded by ADR-NNNN`，而不是删除原文件。代码注释、其他文档和合并请求通过编号引用决策，例如“参见架构决策记录 0007”，不再复制整段设计依据。

## 影响

每项决策的依据只有一个权威位置。新增决策需要新增文件，因此多个决策不会集中修改同一个热点文件。架构决策记录用于说明当时为什么作出该决策；当前组件边界和状态规则由架构文档及代码说明。
