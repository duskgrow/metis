# 0010. 使用扩展 Harness 作为唯一主机运行时

- 状态：已接受
- 日期：2026-11-17

## 背景

Harness 已提供会话持久化、连续事件、多客户端接入、提示词重试和审批，dsh 同时提供 Cordis 插件、profile 与 Web 运行时。额外的 Metis Server 需要重复转发这些能力，并增加一套进程和协议。

本地工作台与远程主机需要相同的主机能力，但运行时的生命周期不同。

## 决策

Metis 通过 Cordis 插件和 profile 将项目文件、Git 操作以及主机、项目与会话之间的映射加入固定版本的 Harness（dsh）。工作台直接连接扩展后的 dsh，使用 Harness 的公开 Web 接口和 Metis 扩展接口。扩展只使用公开接口，不修改 Harness 核心。主机接口需要客户端认证，文件与 Git 操作限定在已打开的项目中。

本地工作台自动启动仅供当前界面使用的扩展 dsh。工作台正常关闭或异常退出时，该运行时及本地智能体随之停止；再次打开工作台会创建新的运行时。用于持续运行或跨设备接入的主机运行常驻扩展 dsh，其生命周期独立于客户端。

同一代码库继续提供无显示运行包和工作台。无显示运行包携带 Node.js、Harness 和 Metis 扩展，Git 使用主机已有的命令；工作台在此基础上加入图形界面、编辑器和 Tree-sitter。

## 影响

主机端 Metis 扩展运行在 Node.js 中，工作台使用 Rust。Harness 与扩展接口通过固定版本和契约测试升级；里程碑 0 首先验证插件边界对项目与 Git 调用、事件和重连的覆盖。
