# Metis 工作台体验与设计边界

本文定义工作台开发需要保持的体验语义和设计边界，是产品体验决策的当前正本。具体变更流程见 [`workbench-ui`](../.agents/skills/workbench-ui/SKILL.md)；当前阶段与下一步见[产品范围与里程碑](product-scope.md)；外部依据与候选视觉方向见 [UI/UX 调研](research/workbench-uiux.md)。首个 Session 工作台的体验规则已经确认，完整冷启动和原生验收仍未完成；原生组件职责、状态映射和计算口径见 [工作台原生组件契约](workbench-component-contracts.md)。

## 体验原则

- **上下文明确。** 页面、审批、错误和通知都应能追溯到主机、项目与会话。跨设备接续是重新接入原主机，不是复制或迁移执行环境。
- **内容优先。** 对话、代码和差异获得最高视觉权重；导航和辅助信息降低存在感。密度来自有效信息和稳定对齐，不来自更多高亮控件。
- **注意力有明确用途。** 待审批、待输入、可恢复失败和待审查与后台正常运行分开表达。例行输出不制造全局打断。
- **状态诚实。** 界面说明实际状态、保留结果、未知信息和恢复路径，不用乐观文案掩盖未验证结果。
- **高频操作高效。** 常用动作有稳定入口和键盘路径；按钮、菜单、命令面板和快捷键共享动作语义。高级诊断渐进展开，高风险信息不得隐藏。
- **可访问性内建。** 键盘、焦点、对比度、非颜色提示、文本缩放和减少动效在组件设计时确定。流式正文、状态播报和系统通知分别处理。

## 领域归属与导航

领域归属固定为 Host → Project → Worktree → Session。单 Worktree 的导航可以压平显示，但不改变领域层级。Worktree 拥有文件和默认 Diff；多个 Session 可以共享同一 Worktree 的文件与 Diff，不能把这些共享事实归给某一个 Session。

Project、Worktree 和父 Session 的 subagent 分别拥有独立的展开状态。展开或折叠一个节点不重置其他节点；折叠 Project 只隐藏子树，恢复后仍保留其中 Worktree 的展开状态。选择或定位 Session 只显露所属路径；Host 过滤只改变可见投影，不销毁上述展开状态。

### 方向性区域导航

工作台按语义区域树组织导航与主区内容，方向移动在可见区域间进行，区域内部仍遵循控件自身的导航规则。`FocusMove` 只表达方向意图，与具体键位解耦；键位由动作层绑定，不属于区域语义本身。

移动焦点不等于选择或切换 Session，也不修改领域事实。Overlay 使用独立焦点 scope，不参与 Shell 的区域移动，关闭时逐层恢复触发来源。审批、Queue 等动态区域出现时不抢焦点；当前目标消失时回退到仍存在且语义相近的区域，并修复后续返回锚点。来源返回与 Back/Forward 恢复对应视图保存的焦点，目标失效时回退到合法主操作区；恢复焦点不回滚 Host、审批或执行事实。

## 主区视图与连续体验

主区同时只呈现 Session、Diff 或只读 Subagent 三种视图之一。Diff 和只读 Subagent 保留清晰的来源与返回路径，返回时恢复来源视图的本地状态和原入口焦点；普通导航与 Back/Forward 只改变视图和本地导航上下文，不回滚 Host、审批、执行、验证或审查事实。

### Agent-first Session 阅读轴

当前 Session 是默认的唯一主阅读轴。有待决定审批时，它是主要行动焦点；否则 Composer 是主要行动焦点。导航、连接和后台进度处于辅助层级，不与对话争夺阅读注意力。

用户消息与模型响应沿同一时间线呈现；工具、审批和结果位于模型响应通道。执行过程采用 Turn → Process group → 单个 Tool 的固定层级，最终或阶段回复留在过程容器外。过程按 Turn、Process、Tool 渐进展开，默认收起已完成细节；运行、失败和停止状态必须保留真实活动与错误入口，不因折叠而不可发现。

### Composer 与 Session 本地状态

Composer 草稿、Queue、焦点、文本选区和滚动位置按 Session 保留。普通切换恢复来源焦点、选区和滚动锚点；流式输出、审批和其他异步更新不得抢走用户已移至草稿或其他控件的焦点，也不得重置选区与滚动。Queue 可编辑和取消，审批完成或重连不自动重放。

Composer 工具行左侧显示当前 Permission；右侧以合并入口呈现 Model + Effort，并放置 Send/Queue 主动作。主动作在在线且空闲时为 Send，在运行中或待审批时为 Queue；Offline 禁止发送和入队，但草稿仍可编辑。Model + Effort 配置按 Session 隔离；合并菜单的 root 分别提供 Model 与 Effort 入口，当前项使用 checked 等非颜色标记。切换模型后采用新模型的 default Effort 和有效 Effort 集合；模型不支持 Effort 时，trigger 和菜单均不呈现该维度。

### Activity、Usage 与 Context

Composer 的辅助统计分为 Activity、Usage、Context 三个独立数据域：Activity 只描述执行活动与耗时，Usage 只描述 token 用量且不表示货币成本，Context 只描述下一次请求的上下文估算。首层提供低强度摘要，各域详情通过自身入口渐进披露，摘要与详情必须来自同一数据域。

三域分别使用独立 Option。某域缺失时只隐藏该域，不补零、不跨域推导；三域均不可显示时不保留空容器。精确公式、舍入和显示格式以 [`stats.rs` 的 rustdoc 与同文件测试](../crates/metis/src/workbench/stats.rs)为正本，不在本文复制。

### Worktree Diff 审查

Diff 是 Worktree 的临时审查页，不是与 Session 平级的持久 tab。从 Session 打开时只把该 Session 作为来源，返回后恢复其草稿、选区、滚动和 Diff 入口焦点；这不改变 Diff 的 Worktree 归属。

Mark reviewed、Feedback 和 Approval 是独立事实与动作。Mark reviewed 只改变审查状态，不发送 Feedback，也不改变验证或 Approval；发送 Feedback 不自动标记 reviewed 或作出 Approval。三者不得互相补齐结果。

### 只读 Subagent

Subagent 是父 Session 的投影，不计入领域 Session 集合，也不进入 Commands 或 Inbox；它不因为被展示而隐式拥有自己的 Worktree。只读 Subagent 视图复用 transcript 投影，不实例化 Composer、审批、Permission、Model、统计或 Diff 等 Session 动作区；continuable 不解锁这些动作。

打开 Subagent 时保存父 Session 的本地状态，返回后恢复父视图与原 subagent 入口焦点，各 subagent 的滚动位置独立保留。

## 状态语义

界面不能用单一“会话状态”替代所有事实。连接、执行、审批决定、行动执行、代码变更、验证和审查是相互关联但独立的信息；实现可以映射现有 Harness 数据，不要求为每条轴另建后端实体。

以下等价关系不成立：

```text
执行完成 ≠ 验证通过 ≠ 用户接受
连接断开 ≠ 执行失败
停止执行 ≠ 撤销文件或外部副作用
后台运行 ≠ 需要用户立即处理
生成补丁 ≠ 补丁已经应用
```

审批必须说明作用域、参数、影响和授权范围。审批失效、被取代或已在其他客户端处理后，不能继续提交旧回答；决定与执行结果都要保留。

审批是同一 tool call 的等待授权阶段，不是独立的工具类型或执行卡。需审批工具在待审批、决定和执行阶段始终保持同一 call 身份；普通工具与需审批工具复用同一 renderer 和 output 结构，审批操作只引用原 call。允许后，运行与结果仍在原 tool call 中呈现，完成后的可见正文与普通工具一致，不保留另一张审批卡或专用结果区；拒绝通过原 output 表达未执行和决定来源，不伪造正常命令输出。其他客户端作出的决定也沿用同一投影，不自动切换当前 Session 或滚动位置。

`SessionPermissionPolicy::AskEachTime` 是当前 Session 的权限策略，要求特权 tool call 分别询问；`AllowOnce` 只授权一个有效 tool call，不修改 Session 策略、不持久化，也不扩展到后续调用。Offline 不改变 Session 策略。Permission 不是 preset 目录，两种作用域不能混淆。

断连、重连或离开页面不能改变已保存状态，也不能把未加载的历史显示成不存在。会话、任务、审批与设备本地状态的所有权见 [Metis 架构](architecture.md)；历史展示不得另建一份可漂移的正本。

连接状态与 Host、事件代际共同决定审批是否仍可提交。Offline/Cached 可以保留历史、结果与草稿，但需要连接的动作不可用；Stale 表示旧代际或旧审批已失效，重连、普通导航和视图往返不能复活旧操作。Host 未明确确认执行结果时必须显示 Unknown，不得推断成功或失败；Not replayed 只描述本客户端没有重放，不是 Host 的执行事实。

## 设计系统边界

### 骨架与主题

新工作台代码通过语义令牌表达表面、前景、边框、焦点、状态、排版、间距、密度和动效，不在页面中分别创造同义视觉决策。

主题可以改变语义令牌的解析值，但不能改变信息架构、区域语义、内容、动作、授权、公共组件 API、键盘行为和状态含义。字体、间距和密度可以触发重排；当前实体、焦点、文本选择、滚动锚点和待处理上下文必须保留。

新增主题能力以 Rust 中的语义令牌为正本，GPUI Theme 只能由其单向派生；实现与对应架构评审在同一变更中落地。出现真实的外部主题或设计工具交换需求后，再引入公共主题格式和生成工具。

### 组件、动作与区域

优先组合现有组件。新的共享组件需要定义用途、类型化 API、组合方式、状态、键盘与焦点、语义令牌、无障碍行为和测试；局部一次性组件不需要独立建设公共抽象。

同一动作由按钮、菜单、命令面板和快捷键共享定义，不分别实现业务行为。新面板进入稳定区域，使用稳定标识和可迁移的布局数据；首版不提供任意位置与任意样式的扩展方式。

界面技术与依赖边界见 [ADR 0006](decisions/0006-use-gpui-kit-for-mvp-ui.md)。

### 演进与例外

共享组件、语义令牌和公共交互模式采用 `Draft → Preview → Stable → Deprecated → Removed` 生命周期。Stable 需要真实使用、契约、文档和测试；移除公共能力需要替代者与迁移路径。局部实现不需要为生命周期另建文档。

偏离既有模式的例外必须在变更中说明范围、理由和回收条件。例外不能因为没有记录而变成新的默认风格。
