# Metis 产品范围与里程碑

Metis 让个人用户在一个工作台中操作多台主机上的智能体，并跨设备接续工作。编辑器用于完成代码修改和差异审查，整体运行方式见 [Metis 架构](architecture.md)。

## 首个可用版本

首个版本先打通本地工作流程，一次打开一个 Git 项目并运行一个活动会话：

1. 在 Linux 上启动 Metis，自动准备运行环境。
2. 添加并打开一个项目。
3. 创建智能体会话，发送提示词并处理审批。
4. 查看和修改代码，审查智能体的改动。
5. 关闭 Metis，结束本地智能体工作。

### 里程碑 1：本地可用

工作台体验与设计边界见[工作台体验](workbench-experience.md)，原生组件职责与验证顺序见[工作台原生组件契约](workbench-component-contracts.md)，外部依据与后续验证方法见[UI/UX 调研](research/workbench-uiux.md)，日常变更流程见 [`workbench-ui`](../.agents/skills/workbench-ui/SKILL.md)。

**当前状态与交付顺序**

当前切片已完成纯行为模型、Light/Dark 主题写路径、Markdown 安全适配、Disclosure、Session headless 纵切、未绑定产品键位的 `FocusTopology`、Host 快照与有序事件的纯投影适配、Host 异步传输与 UI 线程桥接，以及产品入口的本地冷启动；已有行为测试、headless probes、局部 Session 真实帧审查和真实 Host 提示词／审批闭环集成测试通过。原型固化收尾已完成，但这些局部成果不代表完整原生流程已经接通。

[Workbench 产品入口](../crates/metis/src/main.rs)在后台启动私有 Host，打开启动时所在目录并创建 Session，再通过桥接用真实事件更新原生投影；窗口关闭时依次清理传输与 Host。启动失败保持 Offline 并显示错误。当前尚无添加或选择项目的原生流程，也不会自动重连；交互 preview 仍只由 [Session 测试](../crates/metis/src/workbench/session/tests.rs)注入投影和 effect，不是产品运行模式。

Host 投影尚未提供模型与 effort，因此产品 Composer 继续显示 Model unavailable，不能把传输层提示词测试扩大解释为原生提示词主流程已经完成。下一阶段完成 Diff/Subagent 原生 UI、Queue 的真实 Host 提交和模型选择，打通添加项目到差异审查的完整冷启动，最后进行 OS/性能验收。工程接手入口、保留偏差和验证边界由上文组件契约持有。

**本地工作流**

- 一次启动即可使用完整工作台。
- 添加、打开项目，编辑文件并审查差异。
- 创建、接入和取消智能体会话，查看流式输出并完成审批。
- 本地扩展 dsh 随工作台自动启动；工作台正常关闭或异常退出时，该运行时及本地智能体均停止，重新打开时创建新的运行时。

### 里程碑 2：多主机与跨设备

- 通过系统安全外壳协议连接远程主机，提供扩展 dsh 无显示运行包的远程安装、启动和升级。
- 从一台设备管理多台主机上的项目与智能体。
- 从另一台设备接入原主机，继续会话、查看任务和处理审批。

### 里程碑 3：连接与偏好同步

- 增加设备注册、主机发现、连接票据和中继。
- 同步用户偏好，处理版本冲突并保留备份。
- 在设备之间提供一致的连接体验。

### 里程碑 4：发布准备

- 打包 Linux 和 macOS 的无显示运行包与工作台，以及所需资源、许可证和第三方声明。
- 验证真实数据的升级、备份、崩溃恢复和干净机器安装，检查日志中的敏感信息。
